GNN + Conformal Prediction + SVGD

Multi-Robot Robustness-Aware Trajectory Planning

Meeting Brief and Presentation Notes

Prepared 15 October 2026

Main question: Can a trained New GATv2 model, calibrated with conformal prediction, provide a useful robustness signal inside an SVGD trajectory planner—accurately and quickly enough to improve multi-robot trajectories?

1. The 30-second explanation

The professor asked for two connected studies:

  1. Improve dataset construction and batching: avoid unnecessary padding; if padding is required by JIT, make it efficient.
  2. Integrate the GNN and conformal prediction (CP) into the cost used by SVGD. If SVGD is ineffective or too slow, investigate MPPI or MBD.

The current system has an offline learning stage and an online planning stage:

Labeled graphs→Train New GATv2→Saved checkpoint
Calibration graphs→Fit CP correction→Calibrated scorer
Candidate team trajectories→Graphs at future steps→GATv2 + CP cost
Trajectory costs→SVGD updates candidates→Selected joint trajectory
Current result: In one synthetic 10-robot scenario, the simple planner selected a trajectory with minimum exact robustness 1, the soft-degree planner selected 0, and the GNN+CP planner selected 2. GNN+CP took 2.276 s versus 0.333 s for the simple planner. This demonstrates integration, but it is not yet evidence of general performance.
Theoretical correction: the demo uses a robustness threshold of 2 only as a placeholder. If the system uses W-MSR under an F-local adversary model, the usual sufficient scalar threshold is r = 2F + 1. For F = 1, the experiment should target r = 3.

2. What was changed in the training pipeline

Historical representation

Every graph was expanded to 50 node slots and 2,500 edge slots before training. Batches were assembled from graph objects with Batch.from_data_list(). This caused large padded tensors and additional host-side assembly work.

Current “New” representation

Each graph is stored in CPU memory with only its real nodes and edges. When a mini-batch is formed, the real graphs are concatenated. Limited padding is then added to obtain reusable JAX shapes:

  • node capacity is bounded for the batch and includes a disconnected dummy node;
  • edge capacity uses power-of-two buckets to reduce the number of JIT compilations;
  • padding edges point only to the dummy node;
  • padding nodes receive a batch ID outside the real pooling range;
  • a background thread prepares the next host batch while the device processes the current batch.

Padding is still used because JAX normally compiles for array shape. The improvement is that padding occurs at batch construction, with bounded reusable shapes, rather than expanding every stored graph to the global maximum.

5. Conformal prediction

CP does not train the GNN and does not generate trajectories. It uses a separate labeled calibration set to transform model outputs into uncertainty-aware prediction sets or lower bounds.

LAC score

s(x,y) = 1 − p(y | x)

LAC returns a set of plausible robustness classes. For planning, the current implementation uses the smallest member of that set as a lower endpoint.

One-sided robustness score

s = r̂ − ractual

A calibrated quantile q gives the lower bound:

r̲ = clip(ceil(r̂ − q), 0, 25)

At desired coverage 90%, the saved checkpoint produced:

CP resultObserved result
LAC calibration coverage901/1,000 = 90.1%
LAC test-set coverage95/100 = 95%
Mean LAC set size1.18 classes
LAC lower-endpoint coverage97%
One-sided calibration coverage924/1,000 = 92.4%
One-sided test lower-bound coverage94%
One-sided quantile0
The calibration data contain no robustness-zero graphs, while the test data do. Also, the one-sided quantile is zero, so the current one-sided “lower bound” equals the GNN point prediction. CP therefore adds no downward correction in the current planner configuration. These results are empirical coverage measurements, not a trajectory-level guarantee.

6. What one SVGD particle means

In SVGD, a particle is one possible solution. Here, the solution is a complete joint trajectory for the entire robot team:

Zk ∈ RT × N × 2

where k identifies the candidate trajectory, T is the number of future steps, and N is the number of robots.

Current demo quantityValueMeaning
Robots10Ten fixed robot identities with fixed starts and goals
Future steps4Four future positions for every robot
Candidate trajectories / SVGD particles16Sixteen alternative joint trajectories for the same ten robots
SVGD iterations5Five simultaneous updates of all sixteen candidates

One particle therefore contains 4 × 10 × 2 = 80 coordinate values. Each particle produces four communication graphs—one graph at every future step. The 16 particles are not different robot teams.

Initial trajectory sampling

For each robot, the code first interpolates a straight line between its fixed start and goal:

xlinet,i = x0,i + (t/T)(gi − x0,i)

Candidate k is produced by adding seeded Gaussian noise:

x(k)t,i = xlinet,i + ε(k)t,i

7. How the planner turns a trajectory into graph robustness

All robot positions at step t→Edge if distance ≤ radius→Communication graph Gt
Degrees + edges→New GATv2→Predicted robustness
Prediction + CP calibration→Lower bound r̲t→Worst future bound mint r̲t

The GNN does not predict the robots’ positions. SVGD proposes and updates positions; the GNN estimates the robustness of the graphs induced by those positions.

8. Cost used to update trajectories

Let xt,i be robot i’s proposed position at future step t, x0,i its fixed start, gi its goal, R the communication radius, dmin the minimum separation, smax the maximum step, and rreq the required robustness.

The full GNN+CP objective is:

C(Z) = Cgoal + Cmotion + Cseparation + Cstep + Cdegree + CCP
TermImplemented form and purpose
Goalwg mean ||xT,i − gi||²; brings final positions toward goals
Motionwp mean ||xt,i − xt−1,i||²; discourages unnecessary movement
Separationwsep [dmin − ||xt,i − xt,j||]+²; penalizes robots that are too close
Maximum stepwstep [||xt,i − xt−1,i|| − smax]+²
Soft degreewdegree [rreq − d̃t,i]+²; cheap differentiable connectivity heuristic
GNN+CPwCP [rreq − mint r̲(Gt)]+²; penalizes the worst future robustness bound

The differentiable soft degree is:

d̃t,i = Σj≠i sigmoid((R − ||xt,i − xt,j||)/τ)

Graph edges and predicted classes are discrete, so the CP term does not have an ordinary path derivative. The prototype estimates its smoothed gradient using positive and negative random perturbations:

∇CCP(Z) ≈ [CCP(Z+σε) − CCP(Z−σε)] ε / (2σ)

The separation and maximum-step terms are penalties, not hard constraints. Small violations can remain in the selected trajectory.

9. Correct SVGD update order

SVGD does not select a trajectory and then apply repulsion. All candidate trajectories remain active until the final selection.

  1. Create 16 candidate joint trajectories.
  2. Evaluate the cost and cost gradient for all 16 candidates.
  3. Calculate attraction toward lower-cost trajectory regions.
  4. Calculate repulsion between complete candidate trajectories.
  5. Combine both directions and update all 16 candidates simultaneously.
  6. Repeat for the specified number of iterations.
  7. Only then evaluate final costs and return the lowest-cost candidate.

With target density p(Z) proportional to exp(−C(Z)), the update for candidate i is:

Zi ← Zi + η/M Σj=1M[k(Zj,Zi)(−∇C(Zj)) + ∇Zjk(Zj,Zi)]

The first term moves particles toward lower-cost regions. The second maintains diversity between complete team trajectories.

Do not mix up two repulsions: the separation cost repels robots inside one trajectory; SVGD kernel repulsion separates entire candidate trajectories from one another.

10. The three-way ablation

All methods use the same starts, goals, 16 initial candidates, random seed, horizon, and iteration count. Only the planning objective changes.

MethodCost active during SVGDQuestion
simpleGoal, motion, separation, maximum stepWhat happens without a robustness objective?
soft_degreeSimple costs + smooth degree shortfallIs a cheap local connectivity heuristic sufficient?
gnn_cpSoft-degree costs + GATv2/CP robustness shortfallDoes the learned graph-level signal improve selected trajectories?

The simple and soft-degree planners do not query GATv2 while optimizing. After optimization, all selected trajectories are scored by the same GNN+CP evaluator and, for at most 10 robots, the exact exhaustive robustness checker.

11. Current experimental result

Scenario: synthetic 10-robot example, four future steps, 16 candidates, five SVGD iterations, required robustness 2, maximum step 0.20, minimum separation 0.03.

MethodCP boundExact minimum rGoal errorMax stepMin separationShared full costTime

Interpretation:

  • The simple trajectory did not meet the placeholder robustness target: exact minimum r = 1.
  • The soft-degree heuristic performed poorly in this run: exact minimum r = 0 and both soft physical limits were violated.
  • GNN+CP met the placeholder robustness target with exact minimum r = 2 and had the smallest goal error.
  • GNN+CP was about 6.8× slower than the simple method because of repeated graph construction, neural inference, CP scoring, and random gradient probes.
  • The GNN+CP maximum step was 0.201 versus a soft limit of 0.200, showing why hard constraints may be needed.

“Shared full cost” evaluates all selected trajectories with the same full objective, including the CP penalty. It is not merely each method’s private optimization objective.

This is one scenario and one seed. It supports the claim that integration works, not the claim that GNN+CP is generally superior. The soft-degree result could change with weights, iterations, and initialization.

12. Robustness threshold and the role of F

The demo currently contains required_robustness: 2. That value was selected only to create a nontrivial synthetic example.

If the research goal is standard W-MSR resilient consensus under an F-local adversary model, use:

rrequired = 2F + 1

The scalar 2F+1 rule is model-dependent. F-total, asynchronous, local-broadcast, and other consensus settings can use refined conditions such as (r,s)-robustness. The current GNN predicts scalar r-robustness only. Before changing the code, confirm the adversary model and consensus protocol with the professor.

13. What “prototype” means here

The integration is runnable, but the following parts are not yet tied to a physical robot system:

  • the ten starts and goals are synthetic;
  • coordinates use arbitrary units;
  • the distance-threshold communication model is assumed rather than measured;
  • there are no obstacles or full robot dynamics;
  • movement and separation are soft penalties rather than enforced constraints;
  • the planner runs once as a trajectory optimizer; it is not yet an MPC loop;
  • the exact robustness checker is restricted to at most ten robots because exhaustive subset enumeration is expensive;
  • adaptive selection among many queried graphs weakens a direct interpretation of ordinary split-CP coverage;
  • the calibration distribution does not cover robustness zero.

“Prototype” means the component connection has been demonstrated. It does not mean the selected trajectory is ready for execution on robots.

16. Recommended next experiment

  1. Confirm the theory: ask which adversary model, consensus protocol, and F value the professor intends. Derive the correct robustness target.
  2. Confirm graph generation: find how training graphs were produced and determine whether a physical distance-radius graph matches that distribution.
  3. Define physical scenarios: real robot count, starts, goals, time step, communication rule, speed, separation, obstacles, and dynamics.
  4. Run an ablation matrix: simple, soft degree, and GNN+CP across multiple scenarios and at least 10–20 random seeds.
  5. Report distributions: success rate for exact r ≥ threshold, minimum exact r, constraint violations, goal error, mean runtime, and worst-case runtime.
  6. Sweep planner settings: candidate count, horizon, iterations, CP weight, and robustness threshold.
  7. Decide whether to keep SVGD: if success or runtime is poor after reasonable tuning, implement the same three-way objectives in MPPI or MBD.
  8. Move toward MPC only after that: repeatedly observe, plan over a horizon, execute the first control step, and replan.

18. Likely questions and direct answers

QuestionAnswer
What is a particle?One complete joint future trajectory for all robots. Sixteen particles mean sixteen alternatives for the same team.
Does SVGD operate on nodes or graphs?Neither directly. It updates all waypoint coordinates in a joint trajectory. Those positions induce one graph per future step.
What does the GNN predict?One scalar robustness class for the whole graph at each future step.
Why train a GNN if positions are known?Positions determine the graph, but exact r-robustness is combinatorial. The GNN is intended as a fast approximation during many planning queries.
Do we still need training_data.json?Yes for offline training. Planning with an existing checkpoint does not reload the training set.
Is CP a guarantee here?No. It is a calibrated marginal uncertainty estimate; distribution shift and adaptive trajectory selection prevent a direct selected-plan guarantee.
Why 10 robots?It was selected for the synthetic demo because the included exact checker is feasible up to ten robots.
Why 16 candidates?It is a manageable prototype setting, not a theoretically optimal number.
Why is GNN+CP slower?It builds and scores many future graphs and estimates a gradient for a discrete robustness penalty using multiple probes.
Is this MPC?No. It is currently a one-shot trajectory optimizer. MPC would execute only the first step, observe the system again, and replan repeatedly.
Should the target be 2F+1?Yes for the standard scalar r-robustness sufficiency condition under the corresponding W-MSR/F-local assumptions. Confirm the exact system model first.
